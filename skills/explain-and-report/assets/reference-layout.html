生成前的边界正文与图片如何验收补充说明

EXPLAIN / 工作方式与交付边界

让仓库保存规则，让报告留在仓库外

先讲清楚，再生成图文报告。验收留证据，分享有范围，不给代码仓库留下临时产物。

风格：Editorial Technical · 参考状态：候选，未获用户批准

保存位置不是最后一步，而是生成前的边界

这份样例展示同一套排版如何组织结论、流程、比较和补充说明。内容为设计与流程示意，不含真实客户数据，也不代表已经同步到了飞书。

仓库保存规则；外部目录保存结果；飞书按授权分享。
不要先把截图写进项目，再依靠删除或忽略规则防止误提交。

正文图解释机制；验收截图证明页面实际怎么呈现。二者即使都叫 PNG，也有不同的保存和共享范围。

飞书版保留内容，不把整份报告变成图片

文档正文应该可编辑、可检索。流程图可以作为图片插入，但关键解释、图注、数字和来源仍然保留为文字。无法迁移的交互，需要转为静态状态与解释。

表 1 · 按用途决定怎么共享，而不是按扩展名批量上传。
内容本地用途飞书行为
报告正文连续阅读、查看证据可编辑的段落、标题和表格
正文图解说明流程和关键关系按允许清单插入，并补图注

交互细节筛选 Trace、展开补充日志转为关键状态与说明，标注转换限制

这是一份候选设计参考。它可以帮助约束版式，但不能自称是用户已经批准的视觉基准。

验收不是“脚本没报错”

机器检查

记录是否溢出、图片是否加载、目录是否存在，以及无 JavaScript 时核心正文是否保留。

实际看图

判断层级是否清楚、密集区域是否可读、图中文字是否够大，以及关键关系是否容易理解。

两类检查都通过，也不意味着业务分析一定正确。数据与推断需要独立审查；用户是否认可设计风格，也单独记录。

附录只收纳补充内容，不隐藏结论

这张参考图应该学习什么

学习：正文宽度、标题比例、图文间距、图注与表格的关系。不要照搬：示例文案、章节数量或判断它已经通过用户批准。
